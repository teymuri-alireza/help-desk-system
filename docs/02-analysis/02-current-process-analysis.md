# تحلیل فرآیند فعلی (As-Is)

## مراحل فرآیند

در وضعیت فعلی و پیش از استقرار سامانه Help Desk، کاربران دانشگاه شامل دانشجویان و کارکنان مشکلات و درخواست‌های پشتیبانی خود را از طریق کانال‌های ارتباطی مختلف نظیر تماس تلفنی، پست الکترونیکی و مراجعه حضوری به واحد فناوری اطلاعات اعلام می‌کنند.

پس از دریافت درخواست، مسئول یا سرپرست واحد پشتیبانی اطلاعات مربوط به مشکل را به‌صورت دستی ثبت یا مدیریت کرده و آن را برای رسیدگی به کارشناس مربوطه ارجاع می‌دهد. کارشناس پس از بررسی موضوع، اقدامات لازم را برای رفع مشکل انجام داده و نتیجه را از طریق همان کانال‌های ارتباطی به اطلاع درخواست‌کننده می‌رساند.

فرآیند فعلی عمدتاً مبتنی بر ارتباطات مستقیم و مدیریت دستی درخواست‌ها بوده و فاقد یک بستر متمرکز برای ثبت، پیگیری و مدیریت چرخه عمر درخواست‌های پشتیبانی است.

نمودار فرآیند فعلی [As-Is Process Diagram](https://github.com/teymuri-alireza/help-desk-system/blob/docs/document-analysis-phase/diagrams/as-is/current-process.png) به‌منظور نمایش تصویری مراحل فوق در بخش نمودارهای پروژه ارائه شده است.

## نقاط ضعف فرآیند فعلی

بررسی فرآیند موجود نشان می‌دهد که روش فعلی مدیریت درخواست‌های پشتیبانی با محدودیت‌ها و چالش‌های متعددی همراه است.

مهم‌ترین نقاط ضعف فرآیند فعلی عبارت‌اند از:

* پراکندگی اطلاعات در کانال‌های ارتباطی مختلف و نبود یک مخزن متمرکز برای نگهداری درخواست‌ها
* دشواری در پیگیری وضعیت درخواست‌ها توسط کاربران و مسئولان واحد پشتیبانی
* نبود سازوکار استاندارد برای ارجاع، اولویت‌بندی و مدیریت تیکت‌ها
* عدم امکان نگهداری ساختاریافته سوابق درخواست‌ها و فعالیت‌های انجام‌شده
* محدود بودن قابلیت نظارت بر عملکرد کارشناسان و فرآیند رسیدگی به درخواست‌ها
* نبود امکان تهیه گزارش‌های آماری و مدیریتی از وضعیت واحد پشتیبانی
* افزایش احتمال بروز خطا، فراموشی یا از دست رفتن درخواست‌ها به دلیل وابستگی به فرآیندهای دستی

این محدودیت‌ها ضرورت استفاده از یک سامانه یکپارچه برای مدیریت درخواست‌های پشتیبانی را آشکار می‌سازد و مبنایی برای طراحی سامانه Help Desk پیشنهادی فراهم می‌کند.
